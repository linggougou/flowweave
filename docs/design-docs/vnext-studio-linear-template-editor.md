# vNext Studio 线性任务模板编辑器 UX 规格（冻结候选）

- 日期：2026-08-24
- 生命周期：vNext S2-S3，交互与技术映射设计候选
- 实现状态：**尚未实现**
- 产品真源：[后台管理类网站交互式任务模板设计](../superpowers/specs/2026-06-10-backoffice-interactive-task-template-design.md)

## 1. 目标与现状差异

本规格定义 Studio Desktop 第一版线性任务模板编辑与等待输入体验。它不引入画布，也不替换现有项目、任务、运行记录和版本记录结构。

当前真实基线：

| 能力       | 当前实现                                | vNext 目标                              |
| ---------- | --------------------------------------- | --------------------------------------- |
| 任务步骤   | 业务列表、专业表格和 JSON 只读查看      | 在线性列表中插入和编辑输入节点          |
| 变量输入   | 所有 Flow 变量在运行前统一填写          | 在模板定义的位置分段收集                |
| 变量来源   | `FlowDocument.variables[]` 扁平定义     | schema v2 输入节点字段为唯一来源        |
| 变量消费   | `{{name}}` 可递归插值，但无作者界面     | 只在允许字段提供完整 `{{fieldId}}` 绑定 |
| 最近值     | 最近执行可回填变量草稿                  | 普通字段显式选择；敏感字段永不回填      |
| 敏感识别   | `secret_*` 名称猜测                     | 字段显式敏感元数据                      |
| 执行       | `runFlow(...)` 单次 Promise             | 会话可进入 `waitingForInput` 并继续     |
| 进度与取消 | 有 executionId 进度事件和取消           | 保留并覆盖等待输入状态                  |
| 保存       | 可重命名、恢复版本，无 Flow 编辑保存 UI | 显式保存、版本快照、脏状态与冲突守卫    |

## 2. 信息架构

任务页面保留现有主导航“任务步骤 / 运行记录 / 版本记录”。“任务步骤”页增加两种互斥模式：

1. **查看模式**：默认，展示已保存模板，可运行；
2. **编辑模板模式**：编辑草稿，不允许运行未保存内容。

编辑模板模式采用三栏结构：

```text
┌────────────────────────────────────────────────────────────┐
│ 面包屑 / 任务名       未保存       撤销 重做 预览 保存 退出 │
├─────────────┬──────────────────────────┬───────────────────┤
│ 变量来源     │ 线性步骤列表             │ 所选项详情         │
│ 输入节点 A  │ 1 录制步骤               │ 节点 / 步骤字段    │
│  ├ 字段甲   │ + 在此插入输入节点        │ 允许绑定与校验     │
│  └ 字段乙   │ 2 输入节点 A             │ 消费者 / 依赖      │
│             │ 3 录制步骤               │                   │
└─────────────┴──────────────────────────┴───────────────────┘
```

窄窗口下，变量来源和详情面板切为抽屉，但线性步骤列表始终是主区域。第一版不把 JSON 作为编辑入口；原始 JSON 仍留在专业诊断中的只读视图。

## 3. 进入、退出与升级提示

### 3.1 进入编辑

- 查看模式提供“编辑模板”。
- 打开时以当前已保存版本建立本地草稿与撤销基线。
- schema v1 任务必须先显示升级预览：列出将新增的开头输入节点、变量到 `fieldId` 的映射和 schema v2 变化；所有迁移字段的“记住上次输入”默认关闭，作者只能逐字段为非敏感字段显式开启。
- 升级确认摘要必须逐字段展示最终 `remember` 策略；该选择参与 `reportFingerprint`。开启只影响升级成功后新会话接受的输入，不从 v1 默认值、执行历史或旧变量回填中导入最近值。
- 用户确认后只修改草稿，直到保存成功才成为新版本；取消、失败或回滚到 v1 时不得遗留升级预览产生的最近值。
- 取消升级返回查看模式，不改原任务。
- 旧 Flow 的具体迁移和兼容策略以 [Flow Schema、迁移与存储设计](./vnext-flow-schema-migration.md) 为准；Studio 不自行拼装生产 schema。

### 3.2 退出编辑

无变更时直接退出。有未保存更改时统一使用三动作确认：

- “保存并退出”；
- “放弃更改”；
- “继续编辑”。

切换项目、任务、版本、窗口关闭和应用退出均复用该守卫。放弃更改需要二次确认，但不删除已保存版本。

## 4. 线性步骤列表

### 4.1 录制步骤行

每行显示：

- 序号与步骤标签；
- 动作摘要；
- 变量绑定数量；
- 搜索依赖状态（适用时）；
- 错误或高风险标记。

选择步骤后，右侧详情只暴露允许绑定的字段。未开放字段可只读展示，不提供“高级编辑 JSON”绕过限制。

录制步骤不能删除、复制、拖动或重排。作者需要改变网页动作时，应返回扩展重新录制；这条限制在 UI 中明确说明。

### 4.2 步骤间隙

首项之前、每两步之间和末项之后均有键盘可达的“在此插入输入节点”按钮。插入后：

- 创建节点草稿并自动选中；
- 焦点进入节点名称；
- 首个字段由作者显式添加，不生成含真实值的示例字段；
- 节点至少有一个有效字段才可保存。

### 4.3 输入节点卡片

卡片显示：

- 输入节点图标和名称；
- 字段数、必填数和敏感字段数；
- 消费者总数；
- 校验状态；
- “上移到前一间隙”“下移到后一间隙”“删除”菜单。

移动不是拖动专属操作。若移动会使消费者出现在来源之前，操作先展示受影响步骤并被阻止。

删除节点前展示字段及消费者；存在消费者时不允许确认删除，必须先替换或解除绑定。无消费者时仍需确认，确认后进入撤销栈。

## 5. 输入节点与字段编辑

### 5.1 节点详情

右侧详情按顺序包含：

1. 节点名称；
2. 节点说明；
3. 字段列表；
4. 本节点提交后的下一步骤摘要；
5. 节点级校验信息。

名称不能为空。名称和说明只帮助人理解，不参与变量引用；重命名不会破坏绑定。输入步骤 `id` 是规范 `inputNodeId`，但不向普通用户展示。

### 5.2 字段编辑

每个字段展开后提供：

- 标签（必填）；
- 说明；
- 类型：文本、数字、是/否；
- 必填开关；
- 占位提示；
- 普通默认值；
- “敏感输入”开关；
- 普通字段“记住上次输入”开关，默认关闭；
- 消费位置清单；
- 上移、下移、删除。

类型改变会重新校验默认值和所有消费者。不兼容时不自动转换，作者必须处理后才可保存。

开启“敏感输入”时立即执行以下 UI 事务：

1. 清除草稿中的默认值；
2. 关闭并禁用“记住上次输入”；
3. 检查消费者，除 `fill.value` 外均列为阻断错误；
4. 显示“敏感值不会保存或回填，且会收紧本次诊断产物”的说明；
5. 不依赖字段 ID、标签或 `secret_*` 名称推断。

关闭敏感性不会恢复先前默认值或最近值设置。

新建字段与 v1→v2 升级候选都显式保存 `remember: never`。只有作者主动开启非敏感字段开关时才保存 `remember: lastValue`；敏感字段的开关始终禁用，不能通过升级预览、撤销/重做或版本恢复绕过。

字段标签可重复时会造成来源列表难辨，因此同一输入节点内禁止重复；不同节点允许同名，UI 始终连同节点名称展示。`fieldId` 由系统稳定生成且项目内唯一，不随标签重命名变化。

## 6. 变量来源面板

来源树按线性顺序展示：

```text
客户资料（第 2 步输入节点）
  客户名称 · 文本 · 3 个消费者
  联系电话 · 敏感 · 1 个消费者
复核信息（第 7 步输入节点）
  是否确认 · 是/否 · 未使用
```

选择字段后突出显示全部消费者；选择消费者可滚动并聚焦对应步骤。未使用字段显示中性提示，不阻断保存，因为字段可只用于人工确认；但运行预览会列出以便作者复核。

来源树不显示默认值或最近运行值。敏感字段只有敏感标记和消费者计数。

## 7. 行内变量绑定

### 7.1 建立绑定

允许消费位置旁提供模式切换：

- “固定值”；
- “使用输入字段”。

选择“使用输入字段”后，弹出只包含**当前位置之前、类型兼容且符合敏感性策略**的来源列表。选中后显示“节点名 / 字段标签”，不暴露内部 `{{fieldId}}`。

绑定替换整个字段值；编辑器不提供 token 文本框、字符串拼接或表达式编辑。schema v1 的 `{{name}}` 在升级预览中按 G2 迁移映射为完整 `{{fieldId}}`；不能无损转换的内容保持旧版本只读并阻断编辑保存，而不是猜测。

### 7.2 解除或替换

- “改用固定值”时要求作者输入新固定值，不恢复录制时样例作为静默默认。
- “更换来源”保留原绑定，直到新来源确认成功。
- 删除来源时必须先逐项解除或替换消费者。

### 7.3 消费位置与风险

| 消费位置               | 编辑控件                | 额外反馈                 |
| ---------------------- | ----------------------- | ------------------------ |
| `fill.value`           | 固定值 / 文本或数字字段 | 敏感字段可用             |
| `select.values[]` 单项 | 固定值 / 文本字段       | 标出具体数组项           |
| `setChecked.checked`   | 固定值 / 是或否字段     | 无字符串转换             |
| `navigate.url`         | 固定值 / 文本字段       | URL 校验；敏感字段不可用 |
| `wait.urlIncludes`     | 固定值 / 文本字段       | 敏感字段不可用           |
| `role.name`            | 固定值 / 文本字段       | 高风险动态定位确认       |
| `text` 定位策略文本    | 固定值 / 文本字段       | 高风险动态定位确认       |

CSS、XPath、testId、target hints、scope、按键、文件和等待时长保持只读，不提供绑定入口。

## 8. 搜索后选择依赖

### 8.1 作者操作

当某个 `fill` 或 `select` 已把搜索词绑定到非敏感 string 字段时，步骤详情可标记为“搜索驱动步骤”。后续 `click` 或 `press` 提供“依赖的搜索步骤”选择器，只列出此前的搜索驱动步骤。

建立后，列表显示两种不同标记：

- 搜索步骤：“搜索来源：客户资料 / 客户名称”；
- 选择动作：“依赖搜索：第 5 步 输入客户名称”。

关系以规范 `selectionContext.searchStepId` 随模板保存，不能靠相邻关系或当前文案猜测。

### 8.2 不完整状态

下列情况显示阻断错误“搜索选择尚未完成参数化”：

- 被标记为搜索驱动的 `fill` / `select` 没有来源绑定；
- 选择动作没有依赖；
- 依赖步骤位于选择动作之后；
- 依赖步骤被删或不再是搜索驱动步骤。

如果选择动作仍以动态 `role.name` 或 `text` 绑定定位，另显示高风险确认；依赖关系不能消除定位脆弱性警告。

## 9. 校验、预览与保存

### 9.1 校验层级

- **错误**：无法安全解释或执行，阻断保存；
- **警告**：可解释但脆弱，作者在保存时逐项确认；
- **提示**：不阻断，例如未使用字段。

错误至少包括：空节点、空标签、同节点重复标签、默认值类型错误、未来引用、类型不兼容、敏感字段非法消费、孤儿绑定和搜索依赖错误。

警告至少包括：动态 `role.name / text`、无消费者字段、输入节点位于模板末尾、包含敏感字段导致诊断收紧。

### 9.2 运行预览

“预览”打开只读抽屉，以执行顺序列出：

- 浏览器步骤与输入节点；
- 输入节点字段，但不显示默认值内容；
- 字段的消费者数量与位置；
- 搜索驱动与选择依赖；
- 错误、警告和敏感诊断策略；
- 提交每个节点后将继续的下一步骤。

预览不启动 Runtime，也不收集真实值。

### 9.3 保存事务

保存按钮在有脏状态时可用。点击后：

1. 在 renderer 完整校验草稿；
2. 向受控 API 提交期望基线版本和草稿；
3. 主进程/服务再次校验并原子保存；
4. 成功后刷新版本、清除脏状态与撤销栈；
5. 冲突或失败时保留草稿并显示可操作错误。

冲突只提供“重新加载已保存版本”和“继续保留本地草稿”，不自动合并。具体 API、版本令牌和原子性由 G2 规格冻结。

“保存并运行”先完成同一保存事务，成功后才进入现有运行安全确认；不能运行内存草稿。

## 10. 撤销与重做

以下动作进入同一会话级历史：

- 插入、移动、删除输入节点；
- 新增、移动、删除字段；
- 编辑节点/字段属性；
- 建立、替换和解除绑定；
- 建立、替换和解除搜索依赖。

文本连续输入可合并为一次历史项。撤销或重做后立即重新校验。保存成功后以新版本为基线清空历史；版本恢复继续使用现有独立流程，不与草稿撤销混合。

## 11. 运行态输入面板

### 11.1 打开条件与身份

仅当当前活动执行实例收到规范 `input-required` 事件、且 session 进入 `waitingForInput` 状态时打开。Studio 必须以 `executionId`、`sessionId`、`inputRequestId` 和 `inputNodeId` 校验事件属于当前执行、内存会话和一次输入请求；提交值只按 `fieldId` 发送，并用 `clientCommandId` 实现命令幂等。跨窗口、过期或已取消请求不得覆盖当前 UI。

### 11.2 面板结构

输入面板使用 `role="dialog"` 和可访问名称，包含：

1. 状态：“正在等待你的输入”；
2. 任务模板名称；
3. 输入节点名称、说明和步骤位置；
4. 本节点字段表单；
5. 已收集摘要；
6. 下一步骤摘要；
7. “提交并继续”；
8. “取消运行”。

已收集摘要中，普通与敏感字段都只显示字段标签和“已提供”，不回显本次提交值。ACK 后所有字段值均从 renderer 与事件数据面清空，摘要只由 `resolvedFields[].fieldId` 驱动；`aria-live` 也只公告提供状态。面板不得展示 executionId、sessionId、inputRequestId 或内部字段 ID 给普通用户。

每个输入请求固定等待 15 分钟。面板持续显示倒计时，并在剩余 5 分钟和 1 分钟时以 `role="status"` 提醒；提醒不抢焦点、不清空输入。倒计时结束后关闭面板，执行以 `INPUT_WAIT_TIMEOUT` 进入 `failed`，输入节点显示“等待输入超时”，并提供“重新运行”；不显示为取消，也不提供继续或恢复。

### 11.3 字段控件

- string：文本框；敏感时为遮罩输入；
- number：支持本地化输入，但提交前规范化并严格校验；
- boolean：明确的“是 / 否”单选，不使用含混的未勾选状态；
- 必填、说明和错误与控件通过可访问属性关联；
- 敏感输入允许粘贴；显示切换按钮不改变字段值。

首次打开聚焦首个字段；若没有可聚焦字段则聚焦标题。提交校验失败后聚焦首个错误并在顶部提供错误摘要。

### 11.4 提交

- 主按钮文案“提交并继续”。
- 点击后立即进入“正在继续…”，禁用字段、提交和重复取消；这是 `waitingForInput` 下等待命令确认的 UI 忙碌反馈，不新增会话状态。
- Runtime 接受提交后，Studio 立即把所有字段值从控件、组件状态和本地草稿中清空；普通与敏感字段都只通过 `resolvedFields[].fieldId` 留下“已提供”。
- 若提交在 IPC/Runtime 接受前失败，可保留 renderer 当前值供修正；错误对象和 UI 文案不得包含值。
- 重复、过期、跨会话或取消后的提交显示“本次输入请求已结束，未继续运行”，不自动创建新执行。

### 11.5 取消、关闭与退出

- 次级危险动作“取消运行”打开确认，说明浏览器将关闭且本次输入不会保存。
- `Esc`、标题栏关闭和窗口关闭不能静默隐藏面板，统一进入取消确认。
- 取消中显示“正在取消…”，禁止提交。
- 取消完成关闭面板并在进度区显示“已取消”；焦点移回进度状态。
- 应用退出取消会话并清理资源；第一版不支持下次启动恢复。
- renderer 重载可从主进程安全快照重新连回当前等待请求；不恢复重载前任何普通或敏感编辑草稿，只重新应用该请求获准的非敏感 `initialValue`，敏感字段始终为空。
- 窗口关闭、renderer 进程消失或应用退出均取消当前执行，不在后台保留等待请求。

## 12. 运行进度、结果与错误

规范会话状态固定为 `idle / running / waitingForInput / cancelling / completed / failed / cancelled`。现有进度区按下表显示；“正在继续”是命令待确认反馈，不增加规范状态：

| 状态              | 主文案           | 次要信息                  |
| ----------------- | ---------------- | ------------------------- |
| 准备              | 正在准备         | 环境与步骤校验            |
| 运行              | 正在运行         | 当前步骤 / 总步骤、已用时 |
| `waitingForInput` | 正在等待你的输入 | 输入节点名称、下一步骤    |
| 继续中            | 正在继续         | 已安全提交，不显示值      |
| 完成              | 运行完成         | 完成步骤数                |
| 失败              | 运行失败         | 失败步骤和脱敏摘要        |
| 取消中            | 正在取消         | 禁止重复操作              |
| 已取消            | 已取消           | 最后完成步骤与取消位置    |

等待期间进度条不冒充已完成该输入节点；节点只有在提交被 Runtime 接受后才计入完成。

失败结果不提供“从这里继续”，只提供“查看诊断”和“重新运行”。重新运行会创建新执行实例，敏感字段必须重新输入。

## 13. 敏感字段的 UX 安全合同

只要模板含至少一个显式敏感字段，启动确认必须展示：

- 敏感值不会保存到模板、默认值、最近值或普通运行历史；
- HAR 在本次运行全程禁用；
- 从首次敏感输入收集开始，截图和 DOM 快照禁用；
- 敏感值提交后从 Studio 输入控件与草稿立即清除；
- 专业诊断只显示字段存在和“已提供”，不显示真实值。

如果当前诊断配置不能满足上述限制，启动必须被阻断，而不是降级为提醒。

界面不得：

- 根据字段名称猜测敏感性；
- 复制敏感值到日志、错误、toast、DOM data 属性或无障碍公告；
- 在版本差异、JSON 预览或运行上下文中展示敏感值；
- 将遮罩字符串当作可重新提交的真实值；
- 在刷新、返回或重新运行时恢复敏感值。

## 14. 可访问性验收

- 所有功能均可用键盘完成，无拖动专属操作。
- 输入节点、字段、绑定和错误状态不只依赖颜色或图标。
- 步骤列表使用有序列表语义；工具菜单、抽屉和 dialog 有可访问名称。
- 输入面板约束焦点，打开与关闭焦点去向确定。
- 状态使用节制的 `aria-live`；敏感值永不进入公告。
- 200% 缩放和窄窗口下不丢失保存、退出、提交或取消动作。
- 文本、焦点指示、错误与禁用状态达到 WCAG 2.2 AA 对比度要求。

## 15. 端到端验收清单

1. 能从录制 Flow 进入编辑并插入多个输入节点。
2. 能创建 string / number / boolean 字段并按线性作用域绑定。
3. 来源重命名后绑定保持；移动越过消费者被阻断。
4. 每个允许消费位置的类型过滤正确；禁止位置没有绕过入口。
5. 搜索来源与 `selectionContext.searchStepId` 分别展示，缺一即不能标为就绪。
6. 未保存草稿切换上下文会被守卫；保存冲突不覆盖版本。
7. 撤销/重做覆盖所有授权编辑动作，保存后建立新基线。
8. 运行预览无真实执行且能定位所有错误、警告和消费者。
9. 到输入节点后只为当前会话打开面板，并从下一步骤继续。
10. 重复、迟到、跨会话提交均拒绝；取消不显示为失败。
11. 敏感字段无默认/最近值、只绑定 `fill.value`、提交即清空且只显示“已提供”。
12. 含敏感字段时 HAR 全程禁用，首次收集后截图与 DOM 快照禁用。
13. 全流程可仅用键盘完成并由读屏获得不含敏感值的状态。
14. v1 升级预览中所有字段默认 `remember: never`；只有非敏感字段可逐项显式开启，确认指纹覆盖最终策略，且取消、失败或恢复 v1 后无最近值残留。

## 16. 非目标与实现边界

本规格不设计条件、循环、子流程、批量、协作、模板市场、画布、任意表达式、任意 selector 参数化、AI 或关闭后恢复。它也不授权修改 `apps/*`、`packages/*`、数据库、生产 schema 或 IPC。

Studio 实现不得自行复制 DSL 或 Runtime 状态定义。输入节点结构、引用、迁移和搜索依赖以 [Flow Schema、迁移与存储设计](./vnext-flow-schema-migration.md) 为真源；会话、事件、请求身份、提交和取消以 [Runtime 输入会话设计](./vnext-runtime-input-session.md) 为真源。本文件冻结用户可见行为。
