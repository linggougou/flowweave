# 后台管理类网站交互式任务模板设计（vNext-0 冻结候选）

- 初稿日期：2026-06-10
- 本轮冻结日期：2026-08-24
- 生命周期：vNext S1-S2，产品定义与范围冻结候选
- 实现状态：**仅设计，尚未实现**
- 配套 UX 规格：[vNext Studio 线性任务模板编辑器](../../design-docs/vnext-studio-linear-template-editor.md)

## 1. 产品结论

FlowWeave vNext 从“录制后回放工具”演进为面向后台管理类网站的**交互式任务模板工作台**：作者先录制真实流程，再在 Studio 中插入显式输入节点、把后续步骤的有限字段绑定到输入，并以可暂停、可继续、可取消的一次执行实例反复完成同类任务。

vNext-0 只冻结这个最小闭环的合同：

```text
录制线性 Flow
  → Studio 插入输入节点并配置字段
  → 将后续步骤的有限字段绑定到输入来源
  → 保存任务模板
  → Runtime 执行到输入节点进入 waitingForInput
  → Studio 提交本次输入并从下一步骤继续
  → 运行完成、失败或取消且敏感值不进入普通产物
```

本规格不宣称上述能力已经存在。当前实现仍是 schema v1、Flow 级运行前变量表单和一次性 `runFlow(...)`。

## 2. 为什么是任务模板

真实后台任务通常满足两个条件：

1. 页面路径和操作顺序相对稳定；
2. 每次运行的业务数据不同，且部分数据要到达特定上下文后才适合填写。

单纯扩大录制覆盖率不能消除录制时字面值的绑定；统一运行前大表单又会把长流程中不同阶段的输入压在一起。显式输入节点既保留当前线性 Flow 的可理解性，又能表达“一次收集”和“分段收集”。

产品核心单位是**任务模板**，不是输入弹窗、变量或单个步骤；输入节点和变量绑定只服务于模板复用。

## 3. 目标用户、网站与任务

### 3.1 首要用户

第一版服务“录制者自己反复执行”：

- 后台运营人员；
- 实施与交付人员；
- 测试与验收人员；
- 内部管理系统的高频操作者。

作者和执行者在第一版通常是同一个人。信息结构允许未来区分角色，但本阶段不提供分享、权限、审批或多人协作。

### 3.2 目标网站

- B 端运营台；
- CRM / ERP / PMS / 电商后台；
- 以表单、筛选区、搜索、列表和详情页为主要结构的网站。

第一版不承诺覆盖任意消费者网站、验证码、高对抗风控或需要复杂编程的任意网页自动化。

### 3.3 优先任务

1. 新建或修改实体时填写本次业务数据；
2. 用本次输入筛选或查询数据；
3. 搜索实体、从结果中选择目标，并在目标上下文继续固定步骤。

酒店只是示例，产品术语与数据结构不得绑定具体行业。

## 4. 规范术语

| 术语         | 定义                                   | 不使用的替代说法   |
| ------------ | -------------------------------------- | ------------------ |
| 任务模板     | 可保存、复用和执行的线性自动化资产     | 流程程序、编排图   |
| 录制步骤     | 浏览器扩展录制得到的原子网页动作       | 智能节点           |
| 输入节点     | 模板中显式收集本次运行输入的位置       | 弹窗节点、网页弹窗 |
| 字段         | 输入节点内由执行者填写的一项数据       | 全局参数           |
| 变量绑定     | 把后续步骤的允许字段连接到一个输入字段 | 任意表达式         |
| 变量来源     | 产生可绑定值的输入节点字段             | 全局变量池         |
| 变量消费位置 | 使用某个来源值的步骤字段               | 隐式替换点         |
| 执行实例     | 某个任务模板在一次具体运行中的会话     | 批次               |
| 等待输入     | 执行实例到达输入节点后的阻塞状态       | 执行失败           |

跨轨候选规范名为 schema v2 的 `input` 步骤、等于输入步骤 `id` 的 `inputNodeId`、稳定 `fieldId`、整值引用 `{{fieldId}}` 和运行态 `waitingForInput`。搜索选择关系使用 `selectionContext.searchStepId`。这些名字用于设计对齐，不代表生产 TypeScript 已存在。

## 5. 产品模型

### 5.1 线性步骤流

第一版唯一编辑模型是有序步骤列表。录制步骤和输入节点处于同一条时间线；Runtime 从上到下执行，不存在分支、循环、并行或跳转。

作者可以：

- 在步骤之间插入输入节点；
- 编辑输入节点及字段；
- 在允许的步骤字段上建立或解除变量绑定；
- 移动输入节点到另一个步骤间隙；
- 预览、校验并保存模板。

第一版不允许重排或任意改写录制步骤。该限制保护录制路径的可复验性，也避免模板编辑器变成通用编排器。

### 5.2 输入节点

输入节点的产品属性固定为：

- 名称：必填，帮助执行者理解为何暂停；
- 说明：可选，解释数据用途和填写要求；
- 字段列表：至少一项，按作者定义顺序展示；
- 稳定身份：节点的步骤 `id` 同时是 `inputNodeId`，重命名不改变既有绑定；
- 执行位置：节点提交成功后，从它的下一步骤继续。

字段属性固定为：

- 标签：必填，执行者可见；
- 说明：可选；
- 类型：`string`、`number` 或 `boolean`；
- 是否必填；
- 普通字段默认值：可选且必须符合类型；
- 占位提示：仅用于输入提示，不作为提交值；
- 敏感性：显式元数据，不能依赖 `secret_*` 名称猜测；
- 稳定身份：字段使用 `fieldId`，标签重命名不改变既有绑定；
- 非敏感字段“记住上次输入”：作者可显式开启，默认关闭；新建字段和 v1→v2 升级候选都必须先写为 `remember: never`。

v1→v2 升级预览允许作者逐字段把**非敏感**字段改为“记住上次输入”，但该选择必须出现在最终确认摘要中并参与本次升级指纹。开启后也只影响升级成功后新会话接受的输入，不从 v1 默认值、执行历史或旧变量回填中静默生成最近值。取消预览、升级失败或回滚到 v1 都不得遗留该策略对应的最近值。敏感字段始终为 `remember: never`，不能在预览或其他入口改写。

敏感字段的硬限制：

- 不允许配置默认值；
- 不允许开启“记住上次输入”；
- 不从历史或最近运行回填；
- 不允许在预览、版本差异或编辑器中保存真实值；
- 运行态提交后立即清空输入控件和 renderer 本地草稿，只保留“已提供”状态；
- 只允许绑定到 `fill.value`。

### 5.3 变量来源与作用域

schema v2 删除顶层 `variables[]`，输入节点 `fields` 是变量定义的唯一真源。每个字段是一个变量来源。作者在 UI 中通过“输入节点名称 / 字段标签”选择来源，内部以完整 `{{fieldId}}` 绑定，不能混入其他字面量。

第一版作用域只有一条规则：**字段在所属输入节点提交成功后可用，直到本次执行结束**。因此：

- 只能绑定当前步骤之前的输入节点字段；
- 不能引用未来节点；
- 不能跨执行实例复用运行值；
- 不存在嵌套域、节点输出、网页提取值或表达式派生值。

移动输入节点导致其消费者位于节点之前时，保存校验必须阻断并定位所有失效绑定。

### 5.4 有限变量绑定面

第一版编辑器只开放下表；绑定替换一个完整字段值，不支持字符串拼接或表达式：

| 消费位置                   | 允许来源类型    | 产品约束                                         |
| -------------------------- | --------------- | ------------------------------------------------ |
| `fill.value`               | string / number | 敏感字段唯一允许的消费位置                       |
| `select.values[]` 中一个值 | string          | 每次绑定一个选项值，不绑定整个数组               |
| `setChecked.checked`       | boolean         | 只接受布尔字段                                   |
| `navigate.url`             | string          | 保存前校验为可接受的绝对或相对地址；禁止敏感字段 |
| `wait.urlIncludes`         | string          | 禁止敏感字段                                     |
| `role.name`                | string          | 标为“动态定位，高风险”；禁止敏感字段             |
| `text` 定位策略的文本值    | string          | 标为“动态定位，高风险”；禁止敏感字段             |

明确禁止绑定：

- CSS selector、XPath、testId；
- target hints、scopeText 和其他诊断提示；
- 文件路径数组、按键名、等待毫秒数；
- 节点标签、说明或日志文案；
- 混合字面量与变量、函数、条件或任意表达式。

类型不匹配、来源在未来、来源已删除或敏感字段越界时均阻断保存，不做静默转换或字面值回退。

### 5.5 搜索后选择实体

第一版不新增“智能实体选择”复合节点，仍使用原始 `fill / select / press / wait / click` 组合，但必须显式表达两层关系：

1. 搜索驱动步骤：先前 `fill` 或 `select` 的消费位置绑定了哪个非敏感 string 字段；
2. 选择依赖：具体 `click` 或 `press` 的 `selectionContext.searchStepId` 指向哪个先前搜索驱动步骤。

Studio 不能靠步骤相邻关系猜测。UI 同时显示搜索来源和选择依赖。

以下任一情况将模板标为“搜索选择尚未完成参数化”，并阻止以“已就绪”状态保存：

- 搜索输入仍是录制时字面值；
- 选择动作没有显式依赖搜索步骤；
- 依赖指向后续、已删除或不再绑定输入的步骤；
- 选择动作只保留明显对应录制样例的静态定位，且没有经过高风险确认。

高风险确认只表示作者知悉定位仍可能依赖录制样例，不把该步骤包装成稳定或智能选择。

## 6. 用户旅程

### 6.1 作者旅程

1. 在扩展中录制并同步一条可成功回放的线性 Flow。
2. 在 Studio 任务页面选择“编辑模板”。
3. 在需要本次数据的位置前插入输入节点。
4. 配置节点名称、字段、类型、必填、敏感性及普通字段的记忆策略。
5. 在后续录制步骤的允许字段上选择变量来源。
6. 对搜索后的选择动作指定其搜索驱动步骤。
7. 打开运行预览，检查输入点、消费者、高风险定位和敏感诊断限制。
8. 通过校验后显式保存；保存生成新版本。
9. 选择“保存并运行”，进入执行者旅程。

### 6.2 执行者旅程

1. 选择已保存且校验通过的任务模板，确认环境和运行风险。
2. 启动执行实例；Studio 展示实时进度并允许取消。
3. Runtime 到达输入节点后进入 `waitingForInput`，Studio 打开输入面板并说明暂停原因与继续位置。
4. 执行者填写字段；敏感字段默认遮罩，可临时切换可见性。
5. 选择“提交并继续”；提交中防止重复操作。
6. 成功提交后，Studio 立即清空全部本地输入值；普通与敏感字段都只显示字段标签和“已提供”，不回显本次值。
7. Runtime 从输入节点后的下一步骤继续。
8. 执行实例以完成、失败或取消结束，Studio 展示业务结果与脱敏诊断。

## 7. 保存、脏状态与撤销

- 进入编辑模式时建立已保存基线；任一节点、字段、绑定或依赖变更都会显示“未保存”。
- 保存是显式动作，不后台自动保存；`Cmd/Ctrl+S` 与“保存”含义一致。
- 保存前运行完整结构、类型、作用域、依赖与敏感性校验；错误阻断保存，警告需作者明确确认。
- 每次成功保存创建一个版本快照；失败时保留当前草稿，不覆盖上一个可运行版本。
- 撤销/重做覆盖本次编辑会话中的全部授权编辑动作；保存成功后清空撤销栈并建立新基线。
- 切换任务、项目、退出编辑或关闭 Studio 时，如有脏状态，必须选择“保存”“放弃更改”或“继续编辑”。
- 运行不接受未保存草稿；提供“保存并运行”，保存失败则不启动执行。
- 若保存基线已被外部刷新改变，拒绝覆盖并要求重新加载；第一版不做自动合并。
- 删除被消费的字段、删除输入节点或移动节点越过消费者时，先展示影响清单并阻断，直到解除或替换所有绑定。

## 8. 运行预览与运行态反馈

### 8.1 运行预览

运行预览是只读检查，不执行网页动作。它必须展示：

- 模板总步骤、输入节点位置和每个节点字段数；
- 每个字段的消费者数量与位置；
- 缺失绑定、未来引用、类型错误和搜索依赖错误；
- 动态 `role.name / text` 的高风险警告；
- 敏感字段数量及本次诊断产物限制；
- 运行环境、浏览器可见性和现有高风险动作确认。

含敏感字段的模板必须在启动前明确说明：本次运行全程禁用 HAR；从首次敏感输入收集开始，禁用截图和 DOM 快照。该限制优先于诊断便利性。

### 8.2 等待输入

等待态采用 Studio 内的阻塞式输入面板（可访问性 `dialog`），而不是网页自身弹窗。面板必须展示：

- 任务模板名称、输入节点名称和说明；
- “正在等待你的输入”状态；
- 当前在线性步骤中的位置；
- 提交后将继续的下一步骤；
- 本节点字段；
- 此前节点已收集字段的状态摘要，只显示字段标签和“已提供”；
- 主动作“提交并继续”；
- 次级危险动作“取消运行”。

每个输入请求固定等待 15 分钟，面板从打开起展示剩余时间；剩余 5 分钟和 1 分钟时使用不打断输入的状态提醒。超时以 `INPUT_WAIT_TIMEOUT` 进入 `failed`，输入节点记为失败并关闭资源；这不是用户取消，不能继续或恢复，只能重新运行。关闭按钮或 `Esc` 不得让执行实例在后台无提示等待；它们进入取消确认。切换项目、任务或版本在等待期间禁用。

提交成功后立即清空输入控件与本地草稿；普通与敏感值都不回显，ACK 后只允许用 `resolvedFields[].fieldId` 支撑“已提供”状态。提交失败时仅保留尚未离开 renderer 的当前输入供用户修正，错误文案不得包含字段值。请求已过期、执行已取消或不属于当前窗口时，拒绝提交并明确说明执行实例已结束。

renderer 重载后可凭当前会话安全快照重新打开同一个等待请求。重载前的手工编辑草稿一律丢弃；普通字段只重新应用该请求规范投影中的 `initialValue`（仅显式启用 `remember: lastValue` 时才可能使用合法 `lastValue`，否则使用 `defaultValue` 或保持空值），敏感字段始终为空。窗口关闭、renderer 进程异常消失或应用退出均取消执行，不提供后台悬挂或下次启动恢复。

### 8.3 取消与错误

- 运行中和 `waitingForInput` 均允许取消；取消中禁用重复取消和提交。
- 规范状态固定为 `idle / running / waitingForInput / cancelling / completed / failed / cancelled`；“正在继续…”只是提交命令等待确认的 UI 忙碌反馈，不是新增会话状态。
- 取消终态文案为“已取消”，不是“失败”；展示最后完成步骤和取消位置，不展示输入值。
- 字段校验错误同时提供顶部摘要与字段内说明，焦点移至首个错误字段。
- Runtime 在提交后失败时，显示失败步骤、可执行修复建议和重新运行入口；不承诺从失败点恢复。
- Studio 窗口或应用退出会取消当前执行；第一版不提供关闭后恢复等待会话。

## 9. 可访问性与文案

- 目标为 WCAG 2.2 AA；所有编辑、移动、绑定、提交和取消操作必须可仅用键盘完成。
- 拖动不是唯一移动方式；输入节点提供“上移/下移到相邻间隙”操作。
- 输入面板打开时聚焦标题或首个字段并约束焦点；关闭后将焦点还给运行状态区域。
- 每个字段具有关联标签、说明、必填与错误状态；不能只用颜色表达错误、绑定或敏感性。
- 运行状态变化通过 `aria-live` 宣告，但不得宣告输入值。
- 敏感字段的显示切换具有明确按钮名称与 `aria-pressed`；允许粘贴，且不以禁用剪贴板制造虚假安全感。
- 文案始终区分“输入节点”（模板结构）和“网页弹窗”（目标网站界面）。

## 10. 成功标准与验收场景

### 场景 A：开头一次收集

作者在首个网页动作前加入一个输入节点，配置普通必填字段，把它绑定到多个后续 `fill.value`，保存并运行。执行实例先等待输入，提交一次后顺序完成；变量来源和全部消费者可在编辑器中定位。

### 场景 B：中途分段收集

模板先执行登录后步骤，再到第二个输入节点等待。Studio 清楚显示已完成步骤、暂停原因和下一步骤；提交后不从头运行。

### 场景 C：搜索后选择

搜索框绑定实体名称字段，选择动作显式依赖该搜索步骤。预览分别显示“搜索来源”和“选择依赖”；删除依赖或恢复静态搜索词会阻断就绪状态。

### 场景 D：敏感字段

作者将字段标为敏感后，默认值和最近值选项不可用，除 `fill.value` 外的消费位置不可选。运行提交后控件与草稿被清空，界面只显示“已提供”，HAR 全程禁用，后续截图和 DOM 快照禁用，历史与错误中没有真实值。

### 场景 E：脏状态与冲突

作者修改模板后切换任务，Studio 要求保存、放弃或继续编辑。外部版本变化时保存被拒绝，不覆盖远端版本；草稿仍保留。

### 场景 F：取消和过期提交

执行者在等待输入时取消，执行进入“已取消”。随后到达的重复或迟到提交被拒绝，浏览器资源关闭，Studio 不把取消显示为失败。

### 场景 G：可访问性

作者仅用键盘插入并移动输入节点、创建字段、建立绑定和保存；执行者仅用键盘完成输入、修正错误、提交与取消确认，焦点顺序稳定且状态可由读屏获取。

### 场景 H：v1 显式升级与最近值

作者打开 v1 升级预览时，所有迁移字段的“记住上次输入”均默认关闭，旧执行历史不会成为最近值。作者只能逐字段为非敏感字段显式开启，并在确认摘要中复核；取消、失败或回滚不留下最近值，敏感字段始终不可开启。

## 11. 明确非目标

vNext 第一版不做：

1. 条件、循环、子流程、并行或跳转；
2. 批量数据集和无人值守队列；
3. 多人协作、分享、审批、权限、模板市场或云同步；
4. 自动抽取变量、网页数据提取为变量、任意表达式或函数；
5. 任意 CSS / XPath / testId 参数化；
6. 通用节点画布或自由重排录制步骤；
7. AI 改流程、AI 推荐绑定或 P4 产品入口；
8. P3 深度 page / network intelligence；
9. 敏感信息托管、密钥库或跨运行复用；
10. 关闭 Studio 后恢复输入会话或失败点继续；
11. 高级复合“实体选择”节点；
12. 本设计阶段修改任何业务代码、数据库或生产 schema。

## 12. 非阻塞 backlog

下列探索不影响第一版决策，可在后续变更分流中评估：

- enum、日期、文件等更多字段类型；
- 作者与执行者分离后的只运行模式；
- 输入节点模板和字段组复用；
- 更强的搜索结果稳定性分析；
- 普通字段最近值的项目级清理入口；
- 大型模板的分组、折叠和搜索；
- 在明确安全边界后的操作系统密钥库集成。
