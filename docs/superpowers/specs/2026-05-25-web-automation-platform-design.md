# 通用网页流程自动化与页面智能分析平台设计文档

生成时间：2026-05-25

## 1. 产品定位

本产品定义为一个`通用网页流程自动化与页面智能分析平台`。

它不是单纯的网页录制器，也不是单纯的脚本生成器，而是一个能够观察网页、理解网页、操作网页、优化流程、沉淀知识的通用平台。它面向重复性网页工作，把一次人工操作沉淀为可执行、可维护、可优化的自动化资产，并逐步形成对网页项目本身的结构化理解。

## 2. 核心使命

平台需要解决以下核心问题：

1. 重复性网页操作耗时高、易出错，人工执行成本大。
2. 传统录制脚本脆弱，页面轻微变化就会失效。
3. 非技术用户知道自己想完成什么，但不会编写自动化脚本。
4. 测试、实施和开发人员缺少一个统一平台来沉淀页面结构、接口规律和流程知识。
5. 现有自动化通常只追求“能跑”，缺少可解释性、可维护性和持续优化能力。

## 3. 最终产品定义

本产品的最终形态是一个`网页自动化操作系统`。

它的目标不是帮助用户录制一次操作，而是把任意网页系统逐步转化为一个可学习、可执行、可诊断、可复用、可优化的自动化项目。

在这个定义下，一个“项目”包含以下资产：

1. 网站项目档案：域名、环境、入口、依赖说明、常见业务流。
2. 页面知识：页面结构、关键区域、表单、弹窗、列表、分页、上传下载节点。
3. 接口知识：关键请求、参数来源、触发条件、返回结果、鉴权依赖。
4. 流程资产：录制流程、手工编排流程、AI 生成流程、模板流程、版本历史。
5. 执行数据：运行记录、截图、日志、异常原因、成功率。
6. 智能建议：脆弱步骤分析、参数抽象建议、接口替代建议、流程优化建议。

## 4. 目标用户

平台同时服务三类用户，但共用同一套底层能力：

1. 非技术业务人员：关注录制、回放、模板执行、批量处理和结果查看。
2. 测试与实施人员：关注流程稳定性、页面结构分析、接口追踪、失败定位和调试。
3. 开发与自动化工程师：关注脚本控制能力、导出能力、可维护性、AI 协作生成和执行策略。

平台前台可以体现为不同模式，但后台能力必须统一，以避免形成多个割裂产品。

## 5. 产品总体架构

平台由六个核心子系统构成：

### 5.1 录制引擎

负责捕获用户在网页中的操作与上下文，包括：

1. 点击、输入、选择、滚动、等待、跳转。
2. 文件上传、下载、标签页切换、iframe 操作、弹窗处理。
3. 页面截图、DOM 快照、交互节点信息。
4. 用户操作触发的网络请求与页面状态变化。

### 5.2 执行引擎

负责把录制结果转化为稳定的可执行流程，包括：

1. 一键回放。
2. 参数化执行。
3. 批量执行。
4. 定时执行。
5. 断点续跑。
6. 失败重试与错误恢复。

### 5.3 页面理解引擎

负责分析页面本身的结构和交互模式，包括：

1. 页面区域划分。
2. 元素层级与关系识别。
3. 表单、表格、分页、弹窗、筛选区等业务组件识别。
4. 页面关键交互链路识别。
5. 页面脆弱节点标记。

### 5.4 接口理解引擎

负责理解用户操作背后的网络交互，包括：

1. 关键请求识别。
2. 请求与页面动作之间的映射。
3. 参数来源分析。
4. 鉴权依赖识别。
5. 常见错误响应识别。
6. 哪些流程更适合转成接口自动化的判断。

### 5.5 AI 编排引擎

负责把用户意图转成自动化方案，包括：

1. 根据自然语言描述生成流程。
2. 基于历史录制记录复用已有步骤。
3. 基于页面知识与接口知识生成更稳的脚本。
4. 在 UI 自动化与接口自动化之间给出更优建议。
5. 对已有流程提出可维护性和性能优化建议。

### 5.6 项目知识库

负责把每个网页项目沉淀为长期资产，包括：

1. 页面地图。
2. 接口清单。
3. 流程模板。
4. 参数变量。
5. 环境说明。
6. 执行历史。
7. 问题与修复记录。

## 6. 产品使用模式

虽然平台底层统一，但建议前台提供三种使用模式：

### 6.1 业务模式

适用于非技术用户，重点能力包括：

1. 录制流程。
2. 填写参数。
3. 一键执行。
4. 查看执行结果。
5. 使用模板完成重复工作。

### 6.2 分析模式

适用于测试和实施人员，重点能力包括：

1. 查看页面结构。
2. 查看请求链路。
3. 调试流程失败点。
4. 分析流程依赖。
5. 诊断为何某个站点执行不稳定。

### 6.3 专业模式

适用于开发与自动化工程师，重点能力包括：

1. 编辑自动化流程细节。
2. 导出或接管脚本。
3. 调整元素定位策略。
4. 管理执行策略。
5. 与 AI 协同生成更复杂的自动化方案。

## 7. 核心能力边界

平台的核心边界应明确如下：

1. 不是只做“回放”，而是做“流程资产化”。
2. 不是只做“脚本生成”，而是做“脚本 + 知识 + 诊断 + 优化”。
3. 不是面向单个网页，而是面向任意网页项目。
4. 不是一次性工具，而是可持续积累项目知识的长期平台。

## 8. 高价值扩展能力

在完整形态下，建议纳入以下高级能力：

1. 元素自修复：页面变化后自动尝试修复定位策略。
2. 流程模板化：将具体录制结果提炼成通用模板。
3. 变量与数据驱动：一套流程可运行多组参数。
4. 接口替代建议：某些步骤可绕过 UI 时主动提示。
5. 流程体检：识别脆弱节点、登录态依赖、等待策略问题。
6. 可视化调试回放：像录像一样回看每一步执行过程。
7. 网页项目画像：自动总结页面集合、接口集合、业务链路。
8. 自然语言编排：用户描述目标后自动拼装执行流程。
9. 流程组合编排：多个基础流程可组装为完整业务流程。
10. 跨站点协作流程：支持从 A 系统取数据后在 B 系统继续处理。

## 9. 产品价值主张

对三类用户分别体现为：

1. 对业务人员：把重复网页工作从“手工重复”变成“直接调用自动化模板”。
2. 对测试和实施人员：把网页流程从“黑盒执行”变成“可分析、可调试、可诊断”。
3. 对开发与自动化工程师：把网页自动化从“零散脚本”变成“可沉淀、可复用、可协作的平台资产”。

## 10. 设计原则

产品后续详细设计需要遵循以下原则：

1. 统一底座，多角色分层体验。
2. 先沉淀结构化知识，再驱动 AI 生成与优化。
3. 所有流程都应可解释、可复盘、可诊断。
4. 自动化不仅要能跑，还要能维护和演进。
5. 项目是核心对象，流程、页面、接口、参数、执行记录都围绕项目组织。

## 11. 后续设计展开方向

在本设计文档确认后，下一阶段建议继续细化以下内容：

1. 完整功能地图。
2. 产品信息架构。
3. 核心页面设计。
4. 项目数据模型。
5. AI 能力边界与工作流。
6. 权限、协作与企业化扩展能力。

## 12. 一句话总结

这是一个把网页项目“录下来、看懂了、跑起来、持续优化”的通用自动化平台。
