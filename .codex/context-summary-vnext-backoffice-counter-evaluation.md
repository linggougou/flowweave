# vNext 后台管理类网站方向反方评估上下文摘要

## 时间

- 2026-06-10

## 任务目标

- 以“反方 / 挑战者”视角审视 FlowWeave 下一大版本的产品方向。
- 在已确认前提下，识别最容易做错的方向、应砍掉的伪需求、第一版应收紧的边界，以及更合适的产品核心单位与定位名称。

## 生命周期与路线判断

- 当前项目路线锁仍处于 `P2 收口 / v1 先跑通版维护`。
- 本轮不属于当前主线实施，而属于 `S9 后续版本 / 变更管理` 与 `S1 产品定义` 讨论。
- 本轮只输出产品判断，不修改当前版本范围，不解冻 `P3` / `P4`，不落实现方案。

## 已确认前提

1. 当前版本不动，下一大版本聚焦后台管理类网站。
2. 用户理想流程是：先录制，再在 Studio 编辑流程，再显式插入弹窗节点收集运行时输入，后续步骤绑定变量，执行到该节点时再继续。
3. 弹窗节点由流程显式决定，可一次性收集，也可分段收集。
4. 第一版需要覆盖变量填值与常见搜索 / 选择动态流程，但不做无限制高级 DSL。
5. 当前主用户先按“录制者自己反复执行”定义，未来再考虑模板交给同事执行。
6. 产品不能被单一行业样例绑死。

## 关键判断

1. 下一大版本最容易失控的风险，不是能力不够，而是把“动态流程”误做成“万能编排器”。
2. 弹窗节点是交互机制，不应该被抬成产品定义本身。
3. 变量也不是产品核心；变量只是模板的输入面。
4. 如果把第一版做成步骤级可视化编程、多人模板平台或行业专用页面向导，都会偏离最小可复用闭环。
5. 更合适的第一版边界是：面向单人反复执行的“交互式任务模板”，只支持显式输入、有限绑定和常见搜索后选择，不支持无限分支与无限抽象。

## 本轮明确不做

- 不改路线锁。
- 不定义技术实现、数据结构或节点 schema。
- 不引入 AI、协作、批处理平台、开放式 DSL、行业专属术语体系。
