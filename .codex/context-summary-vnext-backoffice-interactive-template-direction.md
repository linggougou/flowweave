# vNext 后台管理类网站交互式流程模板方向上下文摘要

## 时间

- 2026-06-10

## 任务目标

- 基于已确认前提，定义 FlowWeave 下一大版本围绕“后台管理类网站的交互式流程模板”的总体产品方向。
- 输出供团队讨论的一句话产品定义、目标用户与任务边界、MVP 能力、明确不做、方向论证与风险点。

## 路线与生命周期判断

- 当前项目路线锁仍处于 `P2 收口 / v1 先跑通版维护`，主线是“先跑通、再稳定、后智能”。
- 本轮任务不属于当前 v1 主线功能开发，而属于 `S9 后续版本 / 变更管理` 与 `S1 产品定义` 的前置讨论。
- 因此本轮只产出产品方向判断，不改当前版本范围，不解冻 `P3` / `P4`。

## 已确认前提（来自用户）

1. 当前版本先不动，新功能进入下一大版本。
2. 产品先聚焦后台管理类网站，不泛化到所有网站。
3. 下一大版本需要支持：先手动录制流程，在 Studio 编辑录制流程，插入显式弹窗节点收集运行时输入，并在后续步骤中绑定变量。
4. 弹窗是流程里的显式节点，而不是统一的运行前表单。
5. 可在前面放一个大弹窗一次收集，也可拆成多个节点分段收集。
6. 第一版变量不止用于填值，还要覆盖后台常见“搜索后选择”场景，但要收敛，不做无限制万能变量引擎。
7. 酒店只是样例，产品必须可迁移到其他后台站点。
8. 当前主用户先按“录制者自己反复执行”，但信息结构要预留未来“录制者创建、同事执行”。
9. 搜索并选择实体，比直接从列表点击更常见。
10. 下一大版本优先基于原始录制步骤 + 变量绑定，而不是先抽象大量高级节点。

## 关键判断

1. v1 的核心资产已经不是“录制器本身”，而是“录制得到的原始步骤 + Studio 可编辑 + 可重复执行”的闭环。
2. 下一大版本最值得建立的新产品心智，不是“更稳的回放”，而是“可在后台业务里复用的交互式流程模板”。
3. 后台站点中真正高频的参数化场景并非只有表单填值，更多是：
   - 搜索某个实体
   - 从候选结果中选中目标
   - 在合适时点补充上下文信息
4. 如果把所有输入都固定在运行前统一收集，会破坏后台长流程的上下文节奏；显式弹窗节点更符合真实业务流。
5. 第一版不能走“万能变量引擎”路线，否则会在匹配规则、跨页面取值、条件分支和通用表达式上迅速失控。
6. 更合适的收敛方式是：围绕后台高频任务，先把“录制步骤模板化 + 显式输入节点 + 有限类型变量绑定 + 搜索选择型参数”打透。

## 建议的一句话方向

- FlowWeave vNext 应从“录制后回放工具”升级为“面向后台管理网站的交互式流程模板工作台”。

## 本轮明确不做

- 不把本轮讨论直接落为路线锁修改。
- 不定义实现细节、数据结构或技术方案。
- 不把酒店样例提升为产品主场景。
- 不扩展到 AI、云协作、无限制变量引擎或大规模高级节点体系。
