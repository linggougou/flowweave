# 项目上下文摘要（FlowWeave 初始化）

## 1. 参考模式

- `style-shelf-ui`
  - 观察到存在 `.codex/` 与 `docs/`，说明项目级文档和过程记录已经成为固定组织方式。

- `AINovel`
  - 观察到同一根目录下承载多个子项目，说明父级聚合和模块化拆分是可行的。
  - 文档与业务目录并存，适合多能力并行演进。
- `sunshineLinger`
  - 观察到业务目录较直白，说明当模块边界明确时，命名需要尽量可读、少歧义。

## 2. 本次初始化结论

- 选择 `flowweave` 作为仓库目录名，便于跨平台使用。
- 选择 monorepo 作为根结构，避免未来桌面端、扩展端、Web 端和核心引擎拆分时再次迁移。
- 先只创建清晰骨架，不预置具体实现代码，便于后续围绕产品结构继续讨论。

## 3. 初始目录职责

- `apps/`：承载用户直接接触的产品入口。
- `packages/`：承载录制、执行、分析、AI 与共享能力。
- `docs/`：承载产品设计、实现计划和后续文档。
- `examples/`：承载演示流程与样例素材。
- `scripts/`：承载开发和维护脚本。
- `.codex/`：承载上下文摘要、操作日志与验证报告。
